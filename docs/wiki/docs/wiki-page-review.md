# Wiki Page Review

> Audience: Sentinel maintainers, Wiki editors, operations supervisors

This review covers every current Markdown page under `docs/wiki`. Use it as the improvement backlog for making the Wiki easier for first-time Duty Day Staff (DDS), Admin users, and maintainers.

## Review Summary

The Dashboard help pages are the strongest part of the Wiki. They use a consistent structure, plain language, and screenshots. The older day-duty, kiosk, and labeling pages need the most work because they are short, have placeholders, or assume the reader already understands Sentinel.

## Priority Improvements

1. Keep recapturing screenshots whenever visitor, kiosk, check-ins, or Dashboard workflows change.
2. Give every operational page the same structure: what this is, when to use it, what to check, procedure, good/caution/stop, confirm after action, escalate, related pages.
3. Keep role-based paths for DDS, Admin, kiosk operator, and maintainer instead of making users assemble workflows from many separate pages.
4. Add explicit "Sentinel says" versus "real building/person state" mismatch checks to all operational pages.
5. Add short decision guides at the top of hub pages so a user can choose the correct page quickly.

## Suggested Sequencing

1. Publish the DDS pages first so operational users have one complete path.
2. Expand the thin labeling-and-automation pages if they are meant to remain in Wiki.js.

4. Add a quarterly review date to the home page, start page, DDS hub, and all high-risk action pages.
5. Recapture visitor, kiosk, and check-ins screenshots after UI changes.
