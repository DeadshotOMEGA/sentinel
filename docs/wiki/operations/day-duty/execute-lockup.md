# DDS: Execute Lockup

> Audience: DDS, lockup holder, duty supervisors

![Execute Lockup control](/uploads/wiki-dashboard/operations/dashboard-action-open-lockup.png)

Use Execute Lockup only when the building should be secured and Sentinel matches the real situation.

## What This Is

Execute Lockup records that the building has been secured. It is one of the highest-impact actions on the Dashboard because it changes the official building state.

## Preconditions

Before executing lockup, confirm:

- System Status is Healthy enough to trust.
- Security Alerts are reviewed.
- Visitors are checked out or physically accounted for.
- Remaining members are expected or checked out.
- Duty handoff is complete or documented.
- Lockup holder is correct.
- Real building state is ready to be secured.

## Step-By-Step DDS Procedure

1. Review Security Alerts.
2. Filter Presence to Visitors and resolve all visitor status.
3. Review Members and unexpected checked-in people.
4. Confirm Lockup Holder.
5. Confirm the real building is ready to secure.
6. Use Execute Lockup once.
7. Recheck Building Status.
8. If Building Status does not update, capture a screenshot and escalate.

## Good / Caution / Stop

Good: No unresolved visitors, no unexpected members, lockup holder is correct, and Building Status changes to Secured.

Caution: Someone remains checked in but is expected to remain. Document why before lockup.

Stop: A visitor is unaccounted for, lockup holder is wrong, or Sentinel and the real building disagree.
