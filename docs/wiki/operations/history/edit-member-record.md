# Edit Member History Record

> Audience: Managers and admins

![Edit member check-in record modal](/uploads/wiki-dashboard/operations/history-edit-member-record.png)

## What This Is

Member record edit changes an existing member check-in/out row. It should be used for precise corrections, not routine attendance management.

## When To Use It

- The correct row exists but has the wrong direction or timestamp.
- A duplicate scan needs a controlled correction.
- A supervisor authorizes a specific historical adjustment.

## What To Check

- Sentinel says this exact member row is wrong.
- The real member movement is verified.
- The edit reason explains why the original row is inaccurate.

## Step-By-Step Procedure

1. Filter to the smallest record set.
2. Open Edit on the exact member row.
3. Change only the required field.
4. Enter the correction reason.
5. Save and confirm the row changed as expected.
6. Recheck Presence if the correction changes who is on site.

## Good / Caution / Stop Conditions

Good: Only one row changed and the reason is audit-ready.

Caution: Changing direction can affect live Presence and lockup readiness.

Stop: Do not delete or alter records to hide unresolved attendance problems.

## Confirm After Action

- The row timestamp, direction, and person are correct.
- No adjacent row was changed by mistake.

## When To Escalate

Escalate if the edit changes an operational handoff, lockup decision, or attendance dispute.
