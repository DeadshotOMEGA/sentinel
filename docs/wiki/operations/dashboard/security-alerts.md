# Security Alerts

![Security alerts area with an active alert](/uploads/wiki-dashboard/operations/dashboard-security-alerts-active.png)

Security Alerts are the first Dashboard item to review. They are above the status blocks because unresolved alerts can change what actions are safe.

## What This Is

Security Alerts call attention to conditions that may require action before changing building, DDS, lockup, or attendance state. An alert is not handled simply because an Admin has seen it.

## When To Use It

Review alerts at daily start, before lockup, before transfers, after badge problems, and whenever an alert appears during operations.

## What To Check

- Alert type and severity.
- Person, badge, or system affected.
- Time the alert appeared.
- Whether the issue is still true in the real world.
- Whether an acknowledgement note is required.

## Admin Procedure

1. Read each active alert.
2. Confirm the real-world situation.
3. Correct simple issues only if you are authorized.
4. Escalate unclear, unsafe, or unresolved alerts.
5. Acknowledge only after action has been taken or escalation is recorded.

## Good / Caution / Stop

Good: No active alerts remain, or every alert has been handled with context.

Caution: An alert may be old, but you have not confirmed whether the issue still exists.

Stop: An alert affects building security, lockup, missing duty coverage, or an unknown badge.

## What To Confirm After Action

After acknowledgement, confirm the alert count changes and the underlying person/status issue is no longer visible.

## When To Escalate

Escalate if an alert cannot be understood, if the same alert returns, or if the alert suggests unauthorized access or unresolved building state.
